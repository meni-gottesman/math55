Part 1 · Counting (Lectures 14–16)

1Product rule

Idea

If you make a choice in steps, multiply the number of options at each step.

Step 1 has n₁ ways, and for each of those, step 2 has n₂ ways ⟹ n₁·n₂ ways total.
k steps ⟹ n₁·n₂ ⋯ nₖ
Examples from lecture

Time slots Mon–Fri at 1, 2, 3 or 4 pm: 5 days · 4 times = 20.

License plate digit, 3 letters, 3 digits: 10·26·26·26·10·10·10 = 175,760,000.

3 people, 12 offices, all different: 12·11·10. Each person has one fewer choice.

Strings of all 26 letters, none repeated: 26·25⋯1 = 26!

Subsets of an n-element set: each element is in or out, 2 choices each ⟹ 2ⁿ.

One-to-one functions from a set of size n to a set of size m (m ≥ n): m(m − 1)(m − 2)⋯(m − n + 1). Each new value must differ from the earlier ones.

2Sum rule

Idea

If the possibilities split into cases that don’t overlap, add the counts.

|A ∪ B| = |A| + |B| when A and B are disjoint
Example

A password is 6 or 8 digits long. Count: 10⁶ + 10⁸. No password has both lengths, so the cases don’t overlap.

Trap

If the cases do overlap, plain adding counts the overlap twice. Use inclusion–exclusion (§4).

3Division rule (overcounting)

Idea

Sometimes your method produces each outcome several times. If every outcome comes up exactly d times, divide by d.

answer = (ways the procedure can run) / d
Examples from lecture

2-element subsets of {1,…,9}: pick x (9 ways), then y (8 ways) = 72. But {x, y} and {y, x} are the same subset, so each is counted twice: 72/2 = 36.

7-element subsets of {1,…,9}: picking in order gives 9·8·7·6·5·4·3. Each subset appears in 7! orders, so divide by 7! ⟹ 36.

8 people around a round table (same arrangement if everyone has the same neighbors): 8! seatings, but each arrangement appears in 8 rotations ⟹ 8!/8 = 7! = 5040.

4Inclusion–exclusion (two sets)

Idea

For “A or B”: adding |A| + |B| counts the things in both twice, so subtract them once.

|A ∪ B| = |A| + |B| − |A ∩ B|

|A| means the number of elements of A.

Examples from lecture

4-bit strings that start with 1 or end with 0: start with 1 = 2³ = 8; end with 0 = 2³ = 8; both = 2² = 4. Total 8 + 8 − 4 = 12.

Integers 1–100 divisible by 2 or 3: 50 + 33 − 16 = 67. “Divisible by 2 and 3” means divisible by 6, and there are ⌊100/6⌋ = 16 of those.

8-character passwords from 10 digits, 26 letters and 10 special characters (46 symbols) with no special character or no digit: 36⁸ + 36⁸ − 26⁸ (the overlap has only letters).

5Counting the complement

Idea

When “has the property” is messy (especially at least one), count what doesn’t have it and subtract from the total.

#(with property) = #(total) − #(without property)
Example from lecture

Length-10 strings of uppercase letters containing at least one A: 26¹⁰ total, 25¹⁰ with no A ⟹ 26¹⁰ − 25¹⁰.

6Permutations and combinations

  • A permutation is an ordered arrangement of all the objects. An r-permutation is an ordered arrangement of r of them.
  • An r-combination is an unordered choice of r objects, i.e. a subset of size r.
n objects have n! permutations
P(n, r) = n!/(n − r)! = n(n − 1)⋯(n − r + 1)
C(n, r) = (n choose r) = n!/(r!(n − r)!)

Why C(n, r) = P(n, r)/r!: picking r things in order gives P(n, r). Each set of r things appears in r! orders, so by the division rule divide by r!.

Convention: 0! = 1, so C(n, 0) = C(n, n) = 1.

Examples from lecture

Deal one card each to 4 named players: order matters (who gets which) ⟹ P(52, 4) = 52·51·50·49.

5-card hands: order doesn’t matter ⟹ C(52, 5) = 2,598,960.

How to decide

Ask: if I swap two chosen items, is it a different outcome? Yes ⟹ order matters (P). No ⟹ it doesn’t (C).

7Pigeonhole principle

If k + 1 or more objects go into k boxes, some box gets at least 2.

Why: if every box held at most 1, there would be at most k objects. That’s a contradiction.

How to write a pigeonhole proof

  1. Say what the pigeons (objects) are and how many.
  2. Say what the holes (boxes) are, and that there are fewer of them.
  3. Say the rule that puts each pigeon in a hole.
  4. Conclude two pigeons share a hole, then say what that means for the problem.
Examples from lecture

Any 27 English words: two start with the same letter. Pigeons = 27 words, holes = 26 starting letters.

f : A → B with |A| > |B| is not one-to-one. Pigeons = elements of A, holes = elements of B, and a goes in hole f(a). Two elements land in the same hole, so f(a₁) = f(a₂) with a₁ ≠ a₂.

Any n + 1 numbers from {1,…,2n}: one divides another. Write each as 2ᵏ · (odd number) and put it in the hole for its odd part. There are only n odd numbers in 1…2n, so two chosen numbers share an odd part b: 2ⁱb and 2ʲb. The smaller divides the larger.

Every n has a positive multiple written with only 0s and 1s. Take 1, 11, 111, …, (n + 1 ones). Their remainders mod n give n + 1 pigeons in n holes, so two have the same remainder. Their difference (bigger minus smaller) is divisible by n and looks like 11…100…0.

No compression algorithm shrinks every n-bit file. There are 2ⁿ files of length n, but only 2⁰ + 2¹ + ⋯ + 2ⁿ⁻¹ = 2ⁿ − 1 shorter files. So two files compress to the same thing, and the compression can’t be undone.

8Stars and bars (choosing with repetition)

Idea

Choosing r identical things from n types is the same as arranging r stars and n − 1 bars in a row. The bars split the stars into n groups.

ways = C(r + n − 1, r) = C(r + n − 1, n − 1)
Examples from lecture

8 bills from 4 types ($1, $5, $10, $20; same-type bills identical): 8 stars + 3 bars = 11 symbols, choose where the 8 stars go ⟹ C(11, 8) = C(11, 3) = 165.

For example, ★★|★★★★||★★ means two $1s, four $5s, no $10s and two $20s.

Solutions of x₁ + x₂ + x₃ = 17 with every xᵢ ≥ 0: 17 stars, 2 bars ⟹ C(19, 2) = 171.

y₁ + y₂ + y₃ = 14 with every yᵢ ≥ 1: set zᵢ = yᵢ − 1 ≥ 0. Then z₁ + z₂ + z₃ = 11 ⟹ C(13, 2) = 78.

Lower bounds

If xᵢ ≥ c, give xᵢ its c up front: subtract c from the total, then use stars and bars on what’s left.

Which formula? (choosing r from n)

Order mattersOrder doesn’t matter
No repetitionP(n, r) = n!/(n − r)!C(n, r)
Repetition allowednʳC(n + r − 1, r)

9Arrangements with repeated letters

Idea

Arrange as if every letter were different (n!), then divide out the swaps of identical letters, which don’t change the word.

n objects with n₁ of type 1, …, nₖ of type k ⟹ n! / (n₁! n₂! ⋯ nₖ!)
Example from lecture

SENSELESSNESS: 13 letters with 6 S, 4 E, 2 N, 1 L ⟹ 13!/(6!·4!·2!·1!) = 180,180.

10Combinatorial (bijective) proofs

Idea

To prove two expressions are equal, show they count the same collection in two different ways.

Template

  1. Name a specific collection, e.g. “committees of size k from n people”.
  2. Count 1: explain why the count is the left side.
  3. Count 2: explain why the count is the right side.
  4. Same collection, so the two sides are equal.
The identities from lecture

C(n, r) = C(n, n − r): choosing the r you take is the same as choosing the n − r you leave out.

Committee–chair: k·C(n, k) = n·C(n − 1, k − 1). Count committees of k people with one chair. Way 1: pick the committee (C(n, k)), then the chair from it (k). Way 2: pick the chair first (n), then the other k − 1 members from the remaining n − 1.

Pascal’s identity: C(n + 1, k) = C(n, k − 1) + C(n, k). Choose k people from n + 1, one of whom is Alice. Either Alice is chosen (pick k − 1 more from the other n) or she isn’t (pick all k from the other n).

C(n, 0) + C(n, 1) + ⋯ + C(n, n) = 2ⁿ. Both sides count all subsets of an n-element set: by size on the left, by in/out for each element on the right.

Pascal’s identity builds Pascal’s triangle: each inside number is the sum of the two above it. Row n lists C(n, 0), …, C(n, n): 1 · 1 1 · 1 2 1 · 1 3 3 1 · 1 4 6 4 1 · …

A consequence used for Fermat: if p is prime and 0 < k < p, then p divides C(p, k). From the committee–chair identity, p·C(p − 1, k − 1) = k·C(p, k). So p divides k·C(p, k), but p doesn’t divide k.

11Binomial theorem

(x + y)ⁿ = Σj=0n C(n, j) xⁿ⁻ʲ yʲ

Why: (x + y)ⁿ = (x + y)(x + y)⋯(x + y). Each term comes from picking x or y from every factor. You get xⁿ⁻ʲyʲ exactly when y is picked from j of the n factors, and there are C(n, j) ways to choose which.

Example · finding a coefficient

Coefficient of x³y² in (2x − y)⁵. Treat it as (A + B)⁵ with A = 2x, B = −y.

You need B² (for y²), which goes with A³: C(5, 2)·(2x)³·(−y)² = 10·8·1·x³y² ⟹ 80.

Trap

Raise the whole term to the power, including its number and sign: (2x)³ = 8x³ and (−y)² = +y².

Setting x = y = 1 gives 2ⁿ = Σ C(n, j), the identity from §10 again.

Part 2 · Probability (Lectures 16, 18, 19)

12The basic setup

  • Experiment: something with a random result, like flipping two coins.
  • Sample space S: the set of all possible outcomes, like {HH, HT, TH, TT}.
  • Event E: any subset of S, like “both the same” = {HH, TT}.

Equally likely outcomes (Lecture 16)

p(E) = |E| / |S|

Probability is “counting with a denominator”: count the outcomes you want, divide by all outcomes.

Examples from lecture

Two dice, sum is 7: 6 of the 36 outcomes ((1,6), (2,5), …, (6,1)) ⟹ 6/36 = 1/6.

Random number 1–1000 divisible by 5: 200/1000 = 1/5.

General distributions (Lecture 18)

Outcomes don’t have to be equally likely. A probability distribution gives each outcome s a number p(s) with 0 ≤ p(s) ≤ 1 and all of them adding to 1. Then:

p(E) = sum of p(s) over all s in E

The uniform distribution on n outcomes is p(s) = 1/n for each, which gives back |E|/|S|.

Example · a loaded die

Say p(6) = 1/2 and the other five faces have 1/10 each, so the total is 1. Then p(even) = p(2) + p(4) + p(6) = 1/10 + 1/10 + 1/2 = 7/10.

13Poker hands (counting → probability)

All C(52, 5) = 2,598,960 hands are equally likely. Build the hand step by step and multiply.

From lecture

All 5 the same suit: pick the suit (4), then 5 of its 13 cards (C(13, 5)) ⟹ p = 4·C(13, 5) / C(52, 5).

Full house (3 of one rank, 2 of another): rank for the triple (13), rank for the pair (12), which 3 suits (C(4, 3)), which 2 suits (C(4, 2)) ⟹ 13·12·C(4, 3)·C(4, 2) = 3744 hands.

Two pair: choose the 2 ranks together, C(13, 2) (not 13·12, since the two pairs are interchangeable), then 2 suits each (C(4, 2)²), then the fifth card from the other 44 ⟹ C(13, 2)·C(4, 2)²·44.

Trap

13·12 is right when the two ranks play different roles (the triple vs the pair in a full house). When the roles are the same (two pairs), use C(13, 2) or you count each hand twice.

14Complements, unions and the union bound

p(not E) = 1 − p(E)
p(E ∪ F) = p(E) + p(F) − p(E ∩ F)

These are the complement and inclusion–exclusion rules with a denominator. They hold for any distribution.

Examples from lecture

5 coins, at least one head: only “all tails” fails, which is 1 of the 2⁵ outcomes ⟹ 1 − 1/32 = 31/32.

5-card hand with at least two cards of the same rank: the complement is 5 different ranks (C(13, 5)), each in any suit (4⁵) ⟹ 1 − C(13, 5)·4⁵ / C(52, 5) ≈ 0.49.

1–100, divisible by 2 or 5: (50 + 20 − 10)/100 = 3/5.

40% rain, 30% snow, 10% both: p(rain or snow) = 40 + 30 − 10 = 60%.

Union bound

p(E₁ ∪ E₂ ∪ ⋯ ∪ Eₙ) ≤ p(E₁) + p(E₂) + ⋯ + p(Eₙ)

Always true, because you can only over-count the overlaps. It’s useful when the exact union is hard to compute (see §20).

15Conditional probability

p(E | F) = p(E ∩ F) / p(F)   (needs p(F) > 0)

Read it as “the probability of E given F happened.” Once you know F happened, F becomes the whole world, and you ask what fraction of it is also E.

Examples from lecture (two fair coins)

p(second is H | first is H): F = {HH, HT}, E ∩ F = {HH} ⟹ (1/4)/(1/2) = 1/2.

p(both H | at least one H): F = {HH, HT, TH}, E ∩ F = {HH} ⟹ (1/4)/(3/4) = 1/3.

Trap

The two questions sound alike but have different answers, because they condition on different F.

Multiplication rule (the same formula, rearranged): p(E ∩ F) = p(E | F) · p(F).

16Law of total probability

Idea

Split into cases, work out E inside each case, and weight each case by how likely it is.

If F₁, …, Fₙ are disjoint and cover S (with each p(Fᵢ) > 0):
p(E) = p(E | F₁)p(F₁) + ⋯ + p(E | Fₙ)p(Fₙ)

The common two-case form: p(E) = p(E | F)p(F) + p(E | not F)p(not F).

Monty Hall (lecture)

3 doors, 1 car. You pick a door. The host opens a different door showing a goat. Should you switch?

Always switch. Let G = your first pick was a goat (probability 2/3). If G, switching wins for sure; if not G, switching loses for sure.

p(win) = p(win | G)·⅔ + p(win | not G)·⅓ = 1·⅔ + 0·⅓ = 2/3.

Honest answers to sensitive surveys (lecture)

Each person flips a coin: heads means say “yes”; tails means answer honestly. 60% say yes. What fraction of honest answers are yes?

p(yes) = p(yes | heads)·½ + p(yes | tails)·½ ⟹ 0.6 = 1·½ + x·½ ⟹ x = 20%.

17Independence

E and F are independent ⟺ p(E ∩ F) = p(E) · p(F)

If p(F) > 0 this is the same as p(E | F) = p(E): learning F tells you nothing about E.

How to check

  1. Compute p(E), p(F) and p(E ∩ F).
  2. Check whether p(E ∩ F) equals p(E)·p(F).
Example from lecture

A random 4-bit string, all 16 equally likely. E = first bit is 1; F = an even number of 1s.

p(E) = 8/16 = ½ and p(F) = 8/16 = ½. E ∩ F = strings starting with 1 that have an even number of 1s: 1001, 1010, 1100, 1111 ⟹ 4/16 = ¼.

¼ = ½ · ½ ⟹ independent.

Trap

Never assume events are independent unless the problem says so or you check. The lecture called this a very common real-world error.

Pairwise vs mutual independence

  • Pairwise: every pair Eᵢ, Eⱼ is independent.
  • Mutual: the product rule holds for every group of the events, including all of them: p(Eᵢ₁ ∩ ⋯ ∩ Eᵢₘ) = p(Eᵢ₁)⋯p(Eᵢₘ).
Lecture example: pairwise but not mutual

Alice, Bob and Charlotte each pick a random number from 1–100. E₁ = Alice and Bob match; E₂ = Alice and Charlotte match; E₃ = Bob and Charlotte match.

Each has probability 1/100. Any two together (all three numbers equal) have 1/100² = (1/100)(1/100), so they’re pairwise independent.

But if E₁ and E₂ happen, E₃ must happen. So p(E₁ ∩ E₂ ∩ E₃) = 1/100², not 1/100³ ⟹ not mutually independent.

18Bernoulli trials (repeated independent tries)

Repeat a try n times, independently. Each try succeeds with probability p and fails with probability 1 − p. Examples: counting heads in n coin flips (p = ½), or counting 1s in n die rolls (p = 1/6).

p(exactly k successes in n tries) = C(n, k) · pᵏ · (1 − p)ⁿ⁻ᵏ

Why: one particular pattern of k successes and n − k failures has probability pᵏ(1 − p)ⁿ⁻ᵏ, since independent probabilities multiply. There are C(n, k) choices for which tries succeed.

Example

A coin with p(H) = ¼ is flipped 4 times.

Exactly 2 heads: C(4, 2)(¼)²(¾)² = 6 · 1/16 · 9/16 = 27/128.

At least one head: 1 − (¾)⁴ = 175/256.

19The birthday paradox

23 people, each with a uniformly random birthday out of 365. What’s the chance two share one? Use the complement (“all different”) and build the list person by person:

p(some two share) = 1 − (365 · 364 ⋯ (365 − n + 1)) / 365ⁿ

For n = 23 that’s about 50.7%, surprisingly large.

Rule of thumb from lecture: picking n items at random from d possibilities, the chance two match is roughly C(n, 2)/d. There are C(n, 2) pairs, each matching with probability 1/d, and the union bound adds them up.

Lecture’s application: with 64-bit secrets (d = 2⁶⁴), just 2³² of them already give about a 39% chance that two match. That’s why short keys and hashes are unsafe.

20The probabilistic method

Idea

To prove that something with a property exists, build one at random and show the probability it has the property is greater than 0. The usual tool is the union bound: show p(something goes wrong) < 1.

Lecture example · clubs

A school has 10 clubs of exactly 5 students each, and students can be in many clubs. Show you can split the students into red and blue so that no club is all one color.

Put each student on a team by a fair coin flip. One club is all red or all blue with probability 2/2⁵ = 1/16.

Union bound: p(some club is one color) ≤ 10 · 1/16 = 10/16 < 1.

So p(no club is one color) ≥ 6/16 > 0, which means some split works.

Lecture example · infinitely many primes (sketch)

Suppose there were only m primes. Then there are only 2ᵐ squarefree numbers (each prime appears 0 or 1 times).

Pick x uniformly from 1 to n for large n. p(x squarefree) ≤ 2ᵐ/n, which is tiny.

By the union bound over “k² divides x”, p(x not squarefree) ≤ 1/4 + 1/9 + 1/16 + ⋯ < 1, so p(x squarefree) is bounded below by a positive constant. For n large enough these contradict each other.

21Bayes’ theorem

Idea

You usually know p(evidence | cause) but want p(cause | evidence). Bayes flips the condition around.

p(F | E) = p(E | F)·p(F) / p(E)
= p(E | F)p(F) / [ p(E | F)p(F) + p(E | not F)p(not F) ]

Why: by the definition, p(F | E)·p(E) = p(E ∩ F) = p(E | F)·p(F). Divide by p(E), then expand p(E) with the law of total probability.

Lecture example · cancer test

1% of people have it. The test is positive for 90% of people who have it and negative for 90% of people who don’t (so 10% false positives).

p(cancer | positive) = (0.9 · 0.01) / (0.9 · 0.01 + 0.1 · 0.99) = 0.009/0.108 = 1/12 ≈ 8.3%.

Sanity check with 1000 people: 10 have it and 9 of them test positive. 990 don’t, and 99 of them test positive. Only 9 of the 108 positives are real.

Lecture example · librarian or farmer?

Someone says they love to read. p(loves reading | librarian) = 99%, p(loves reading | farmer) = 40%, and there are about 30 farmers per librarian.

p(librarian | loves reading) = 0.99·1 / (0.99·1 + 0.4·30) ≈ 7.6%. A farmer is still far more likely.

Trap

p(A | B) ≠ p(B | A). How common something is to begin with (the 1%, or the 30 : 1 ratio) matters a lot.
